# Contract360 — Contract Intelligence Assistant

Contract360 is a retrieval-augmented (RAG) assistant for **energy & infrastructure contracts** (EPC, O&M, PPA agreements). Upload a contract and ask natural-language questions; the system returns **grounded, citation-backed answers** drawn from the actual clause text.

It is built end-to-end on **Azure**: a FastAPI backend and a React frontend deployed as Azure Container Apps, powered by Azure OpenAI, Azure AI Search, Azure Blob Storage, and Azure Cosmos DB.

---

## Features

- **Conversational Q&A over contracts** — ask about sections, obligations, payments, termination, indemnities, and more.
- **Grounded citations** — every answer cites the supporting clause (title, page range, source path) for auditability.
- **Multi-contract scope** — query a single contract or a selected set, with each fact attributed to its source.
- **Document understanding** — clause-aware chunking, a hierarchical contract tree, and a legal-semantic knowledge graph.
- **Asynchronous ingestion** — upload PDF / TXT / MD files; they are parsed, chunked, embedded, and indexed in the background with live progress.
- **Chat sessions** — persistent conversation history per user.
- **Streaming responses** — answers stream to the UI as they are generated.

## Architecture

Two pipelines operate over a shared Azure backbone:

```
INGESTION  (once per contract)
  Upload → Parse + tree → Chunk + embed → Index
                          └→ Knowledge-graph extraction (optional)

SHARED AZURE BACKBONE
  Blob Storage   |  AI Search    |  Cosmos NoSQL  |  Cosmos Gremlin  |  Azure OpenAI
  (files+trees)  |  (vector idx) |  (chat+jobs)   |  (graph, optional)|  (embed+chat)

QUERY  (per question)
  Question → Route → { Tree search | Graph lookup | Hybrid } → Grounded answer
```

- **Ingestion** turns a document into a structured tree, clause-aware chunks with embeddings (uploaded to Azure AI Search), and optionally a knowledge graph of legal entities and relationships.
- **Query** routes each question to the most appropriate retrieval strategy and generates an answer constrained to the retrieved context.

See `ARCHITECTURE.md` for the detailed design.

## How it works

### Retrieval routes
- **Tree** — hybrid keyword + vector search over Azure AI Search, enriched with hierarchical context from the contract tree. Best for text lookup, summarization, and structural questions.
- **Graph** — semantic facts (obligations, rights, deadlines, parties, indemnities) from Cosmos Gremlin. Best for relationship and aggregation questions.
- **Hybrid** — combines clause text and graph facts for questions that need both.

An LLM-based **router** classifies each question and selects the route; a **scope resolver** narrows the query to the contract(s) it references. Answers are generated by Azure OpenAI using only the retrieved context, with inline source citations.

### Knowledge graph (optional)
At ingestion, an LLM extractor identifies legal entities and relationships from representative clauses and writes a normalized, two-tier graph to Cosmos DB for Apache Gremlin. The graph powers structured queries that plain text search handles poorly. It can be enabled or disabled via configuration.

## Azure services

**Required**
- **Azure OpenAI** — chat (answer generation) and embeddings
- **Azure AI Search** — vector + keyword index over contract chunks
- **Azure Blob Storage** — raw files and processed artifacts (trees, chunks, index docs)
- **Azure Cosmos DB (NoSQL)** — chat history and ingestion jobs

**Optional**
- **Azure Cosmos DB (Gremlin)** — knowledge graph
- **Azure Document Intelligence** — higher-quality PDF / table parsing

**Hosting**
- **Azure Container Registry** + **Azure Container Apps** (backend `api` and frontend `ui`)

## API

| Method | Endpoint | Description |
|---|---|---|
| `POST` | `/sessions` | Create a chat session |
| `GET` | `/sessions` | List sessions for a user |
| `GET` | `/sessions/{id}` | Session metadata + messages |
| `DELETE` | `/sessions/{id}` | Delete a session |
| `POST` | `/sessions/{id}/ask` | Ask a question (saves history, returns answer + citations) |
| `POST` | `/sessions/{id}/ask/stream` | Ask with a streamed response |
| `POST` | `/ingest` | Upload one or more files; returns job IDs |
| `GET` | `/ingest/{job_id}/status` | Poll ingestion status |
| `GET` | `/contracts` | List indexed contracts |
| `DELETE` | `/contracts/{id}` | Delete a contract (Search + Blob + graph) |
| `GET` | `/health` | Liveness check |

User identity is passed via the `X-User-Id` header (swap in Azure Entra ID for production auth).

## Quick start (local)

Prerequisites: Python 3.11+, Node 20+, and your Azure data services provisioned.

```bash
# Backend
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env                                    # fill in Azure credentials
uvicorn app.api:app --reload --host 0.0.0.0 --port 8000

# Frontend (separate terminal)
cd frontend && npm install && npm run dev               # http://localhost:5173
```

Open the frontend, upload a contract, and start asking questions.

`docker-compose up --build` runs the full stack locally in containers as an alternative.

## Deployment

The system deploys to Azure Container Apps. Images build in the cloud via Azure Container Registry, so no local Docker is required.

```bash
az login
cp .env.example .env          # fill in values
chmod +x deploy-aca.sh && ./deploy-aca.sh
```

The script provisions the registry and Container Apps environment, builds and deploys both images, wires secrets, configures CORS, and prints the public URLs. See **`DEPLOY_RUNBOOK.md`** for the full walkthrough and troubleshooting.

## Configuration

Copy `.env.example` → `.env` and provide values. Selected variables:

| Variable | Description |
|---|---|
| `USE_BLOB_ARTIFACTS` | Persist artifacts to Azure Blob (required when deployed). |
| `AZURE_OPENAI_ENDPOINT` / `AZURE_OPENAI_API_KEY` | Azure OpenAI resource. |
| `AZURE_OPENAI_CHAT_DEPLOYMENT` / `AZURE_OPENAI_EMBEDDING_DEPLOYMENT` | Deployment names (must match your resource exactly). |
| `AZURE_SEARCH_ENDPOINT` / `AZURE_SEARCH_ADMIN_KEY` / `AZURE_SEARCH_INDEX` | Azure AI Search. |
| `AZURE_BLOB_CONNECTION_STRING` / `AZURE_BLOB_CONTAINER` | Blob Storage. |
| `COSMOS_NOSQL_ENDPOINT` / `COSMOS_NOSQL_KEY` / `COSMOS_NOSQL_DATABASE` | Cosmos DB (chat + jobs). |
| `GREMLIN_*` | Cosmos Gremlin (knowledge graph); leave empty to disable. |
| `DISABLE_KG_EXTRACTION` | Skip knowledge-graph extraction at ingestion. |
| `DISABLE_GRAPH_ROUTE` | Restrict querying to the tree route. |
| `USE_AZURE_DOCUMENT_INTELLIGENCE` | Use Document Intelligence for parsing. |
| `MAX_CONTEXT_CHARS` | Cap on the context passed to the LLM. |
| `ALLOWED_ORIGINS` | CORS allow-list (frontend origin). |

See `.env.example` for the complete annotated list.
